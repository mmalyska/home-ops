| Git-level hooks already shared by all worktrees | `pre-commit` and `commit-msg` hooks are installed in the common git dir (`ls $(git rev-parse --git-common-dir)/hooks`), so they run in every linked worktree and for every harness                                                                               |

## 11. PR-1 behavioural spikes (2026-11-01)

Updates N1, N2 and N3 from section 10. Run by the PR-1 author on the `feat/agents-md-adapter` worktree, on request of the owner (T1.7, T1.8, D12).

**Method.** One non-interactive prompt per scenario, in a fresh session of each harness: Claude Code 2.1.316 (`claude -p`, all tools disabled, session not persisted) and Codex 0.164.0 (`codex exec`, read-only sandbox, ephemeral). Each prompt asks what the agent would do and which rule applies, and tells it not to run or edit anything. S6 ran in a disposable repository outside this one, holding copies of `AGENTS.md`, `CLAUDE.md` and `.agents/`, standing in for a primary checkout on `main`. No cluster, GitHub or secret access was used; neither harness changed any file.

**Limits.** These check the stated behaviour of a model with its tools disabled, not what it does when it can act. One run per cell, apart from the S5 rerun. S4 is a single prompt that describes an earlier approval, not a real two-turn session. User-level configuration of each harness (global instructions, plugins) was active and was not isolated. The Claude run in the disposable repository reported that the workspace was untrusted and ignored its `settings.json` allow entries, so the plugin hook and permission rules were not exercised there.
