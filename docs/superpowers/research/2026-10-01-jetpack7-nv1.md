# Research: JetPack 7 (CUDA 13) and a faster carrier board for nv1

Date: 2026-10-01. Status: research only, nothing changed in the repo or cluster.

## Question

What would it take to run JetPack 7 (CUDA 13) on nv1 under Talos, with a new carrier board as an enabler for MAXN Super power mode? Is it feasible, and is it worth it?

Today nv1 is a Jetson Orin NX 16 GB on a standard Seeed reComputer J401 carrier board. It runs Talos with the `schwankner/talos-jetson-orin` image: JetPack 6 / r36.5 userspace, OE4T-built `nvgpu` and host1x/DRM modules, Talos mainline kernel 6.18. The power-mode DaemonSet blocks MAXN Super on this board.

## Findings

### 1. JetPack 7 supports Orin NX now

- JetPack 7.2 (Jetson Linux 39.2, announced about June 2026) is the first JetPack 7 release that supports the Orin family (AGX Orin, Orin NX, Orin Nano) as well as Thor. JetPack 7.2.1 (Jetson Linux 39.2.1) shipped 2026-08-11.
- Stack: kernel 6.8 (Orin: `linux-noble-nvidia-tegra`, 6.8.12, replacing the 5.15 `linux-jammy-nvidia-tegra`), Ubuntu 24.04 userspace, CUDA 13.2.x, cuDNN 9.20, TensorRT 10.16.2.
- Orin NX 16 GB in MAXN Super is documented as up to 157 TOPS at up to 40 W (that mode arrived with JetPack 6.2; JetPack 7.2 keeps it).
- Early-adopter issues reported on JetPack 7.2 Orin (stock Ubuntu):
  - Prebuilt Ollama has no sm_87 kernels and falls back to CPU.
  - No official Python wheels for JP7.x.
  - Frigate/onnxruntime-gpu have no prebuilt JP7 path.
  - Forum report of GPU not initialising because of a missing firmware directory (unconfirmed; the NVIDIA thread I found blamed Ollama builds instead).
- The ecosystem is still catching up. A CUDA 13 llama.cpp build that includes sm_87 should be fine; CUDA 13 still supports Ampere.

Sources: [JetPack downloads](https://developer.nvidia.com/embedded/jetpack/downloads), [JetPack overview](https://developer.nvidia.com/embedded/jetpack), [JetPack 7.2 announcement](https://forums.developer.nvidia.com/t/jetpack-7-2-jetson-software-goes-agentic-with-jetson-linux-39-2/372059), [OE4T r39.2 notes](https://github.com/OE4T/meta-tegra/blob/master/docs/release-notes/JetPack-7.2-L4T-R39.2.0-Notes.md), [JP7.2 GPU forum thread](https://forums.developer.nvidia.com/t/jetpack-7-2-gpu-acceleration-issue/372521), [jetson-ai-lab #427](https://github.com/NVIDIA-AI-IOT/jetson-ai-lab/issues/427).

### 2. The board does not gate JetPack 7. It gates MAXN Super.

- Seeed's J401 flashing guide covers JetPack 7.2 (L4T 39.2.0) for Orin NX 16/8 GB on the standard J401 carrier. Seeed also repeats the warning: do not enable MAXN SUPER on the standard J401, because cooling is insufficient and the module can be permanently damaged.
- This corrects the 2026-09-28 TODO entry, which implied the Super board was the route to JetPack 7.2. The board and JetPack 7 are independent upgrades. The only hard gate for JetPack 7 is Talos support (finding 3).

### 3. Talos is the real blocker

- Upstream state:
  - `schwankner/talos-jetson-orin` is pinned to JetPack r36.5 userspace and nvgpu 5.13 from OE4T's r36 sources. Its README has no JetPack 7/r39 roadmap.
  - Sidero's `siderolabs/pkgs` PR #1518 (`nvidia-tegra-nvgpu`) is open and on hold. It targets kernel 6.18+ and JetPack 6 (CUDA 12.6). Maintainers raised firmware licensing concerns. No r39 mention.
  - NVIDIA does not endorse running its out-of-tree Tegra modules on a mainline kernel. The forum thread on this ended with a workaround: build `tegra-drm`, `host1x-nvhost` and `nvhwpm` from the same OE4T tree as `host1x`, so the DRM ABI matches.
- What a port to r39 would involve (my assessment from the above; not confirmed by any source):
  1. Rebase the OE4T nvgpu/host1x/nvmap/tegra-drm set from the r36 (5.15) sources to the r39 sources, which target 6.8.12, then carry them to Talos' 6.18 kernel. That is two kernel-API jumps of out-of-tree driver code, not one.
  2. Keep nvgpu and userspace in lockstep: `libcuda`/`libnvrm_gpu` from r39 must match the r39 nvgpu ABI. Our CDI setup DaemonSet currently downloads r36.5 debs; it would switch to r39 debs plus `nvidia-l4t-firmware` r39.
  3. Re-validate the Orin boot chain. JetPack 7 changes the UEFI/QSPI firmware handling ("follows the approach used for Thor"). Talos boots via UEFI, so the firmware needs flashing from a Linux host, and boot may change. Unknown until tried.
  4. Rebuild the Talos installer image and re-test CDI, the device plugin, and the llama-server images (all pinned to CUDA 12.6 today).
- Size: comparable to, probably bigger than, the original bring-up in `docs/superpowers/plans/2026-08-13-jetson-igpu.md`, which was done with a known-good upstream recipe. This one has no recipe yet.
- Cheapest lever: ask `schwankner` (open an issue) whether r39 is planned. They already do the same port for r36 and track the same hardware.

### 4. Risk to check first: GPC0-floorswept Orin NX 16 GB modules

- A forum report describes kernel SLUB heap corruption in nvgpu GPU power-on on Orin NX 16 GB modules (part 699-13767-0000-301) with GPC0 floorswept (`gpc_fs_mask=2`), confirmed on JetPack 6.2/r36.4.3; later versions were not tested. NVIDIA had not acknowledged it as a known issue.
- nv1 has run stably for weeks, so it is either not this SKU or not affected. Before any migration, read nv1's part number and GPC mask. Not done here.

Source: [forum report](https://forums.developer.nvidia.com/t/orin-nx-ga10b-kernel-slub-heap-corruption-in-nvgpu-gpu-power-on-gr-ecc-init-on-gpc0-floorswept-modules/372967).

### 5. Carrier board candidates

Requirement: officially supports JetPack 7.x or flashes with the official JetPack SDK, and sustains MAXN Super (40 W).

| Board | Super/MAXN | JetPack 7 | Price | Notes |
| --- | --- | --- | --- | --- |
| **Seeed reComputer Super J401** (bare board) | Yes, designed for it | Yes, JP 7.2 stated | $159 ($149 at 10+) | Same maker and form as the current board; the reComputer Super J4012 is this board in a case with a module. Best fit. |
| **Waveshare JETSON-ORIN-IO-BASE** | Waveshare's dev kit page says the Super upgrade is supported (JetPack 6.2); thermal rating for 40 W not stated | Not stated | Board price not captured; dev kits $911-$1,461 | Near-reference-board I/O: 2x M.2 Key M, Key E, 1x 1GbE, 4x USB 3.2, fan header, 9-19 V DC input. Likely flashes with the stock NVIDIA flow (inferred, not confirmed). Needs its own cooling plan. |
| **Connect Tech Hadron-DM** | Yes, Super-compatible | Not checked | Not checked | Industrial class; likely overkill and expensive. Only skimmed. |
| NVIDIA Orin Nano Super dev kit carrier | Yes, but it is a Nano/NX reference design | Yes, ISO flash default | Not checked | Not checked in depth. Another option if a reference board is wanted. |

I did not find other boards with explicit JetPack 7 plus MAXN Super statements. The search was not exhaustive (Forecr, Advantech, Auvidea and others were not checked).

Things the board swap changes on the Talos side:

- NIC name: the node config uses `enP8p1s0`. A different carrier's PCIe topology or NIC chip can change it. Re-check with `talosctl get links` after the swap and update `provision/talos/nodes/nv1.yaml`.
- Disk: the NVMe device layout can change. Re-check the Talos install disk selector.
- DHCP: after any reflash or reinstall, re-check the META `0x0a` key (see `docs/src/k8s/nv1-jetson.md`).
- Power: 40 W needs an adequate supply (19 V brick) and real cooling. The Seeed Super board's J4012 design is the one with explicit thermal engineering.

Sources: [Seeed Super J401](https://www.seeedstudio.com/reComputer-Super-J401-Carrier-Board-p-6642.html), [Seeed reComputer Super J4012](https://www.seeedstudio.com/reComputer-Super-J4012-p-6443.html), [Seeed J401 flash guide](https://wiki.seeedstudio.com/reComputer_J4012_Flash_Jetpack/), [Waveshare IO-BASE](https://www.waveshare.com/product/ai/jetson-orin-io-base.htm), [Waveshare Orin NX dev kit](https://www.waveshare.com/jetson-orin-nx-16g-dev-kit.htm), [Connect Tech Super mode](https://connecttech.com/jetson-orin-nx-nano-super-mode/).

### 6. What each upgrade is worth

- **MAXN Super (board swap, JetPack 6 line, no Talos changes):** 40 W, 157 TOPS marketing figure. LLM decode on nv1 is mostly memory-bandwidth bound (unified memory shared with CPU), so the real tok/s gain is probably smaller than the TOPS ratio. Not measured; it needs a before/after test with the existing llama-server and the sustained-load memory test described in `docs/src/k8s/nv1-jetson.md`. Cheap and reversible.
- **JetPack 7 / CUDA 13:** no new silicon capability on Orin. The value is ecosystem currency:
  - mainstream upstream aarch64/SBSA containers;
  - current upstream vLLM (v0.22+ needs CUDA 13), which is the blocker for running LFM2.5-8B-A1B on vLLM (`.plans/TODO.md`, 2026-10-01);
  - TensorRT Edge-LLM (needs 7.2+).
  Against that, early JetPack 7.2 Orin reports show rough edges, and the cost is a Talos driver port.

## Options

| | What | Effort | Risk | Payoff |
| --- | --- | --- | --- | --- |
| A | Stay as is | none | none | none |
| B | Buy Seeed Super J401 ($159), move module, stay on r36.5 Talos, enable MAXN Super | Low: a swap, a node-config check, a power-mode DaemonSet change | Low; thermals and 40 W supply need checking | Possible tok/s gain; measure first |
| C | B, then port Talos image to JetPack 7 (r39) | High: out-of-tree driver rebase across two kernel jumps plus userspace and boot-chain work | High: no upstream recipe; nv1 is the only GPU node, so downtime and rollback must be planned | CUDA 13, upstream vLLM, newer containers |
| D | Ask upstream (`schwankner`) about r39; wait | Minimal | none | Possibly free port later |

## Recommendation

1. Do D now: file an upstream issue asking about r39 support and share what this research found. It costs nothing.
2. Do B next. It is the only change with immediate, measurable value. Buy the Seeed Super J401, keep the module, and measure before and after. The Seeed board is the safest pick because it names both JP 7.2 and MAXN Super; the Waveshare base board is the fallback if Seeed stock or price is a problem.
3. Treat C as a separate project, started only when the vLLM/CUDA 13 payoff justifies a research-grade port (or upstream does the work). If you start it, develop it on a bench setup rather than on nv1, since nv1 is the only GPU node.
4. Before B or C: read nv1's module part number and GPC floorsweep mask (finding 4) and capture the current MAXN baseline tok/s and power draw.

## Open questions

- Does JetPack 7 on Orin still ship nvgpu as the GPU driver? The release notes I read only mention the out-of-tree module package being updated for 6.8; they do not name nvgpu. Treat nvgpu as probable but verify against the r39.2 source tarball.
- Can Talos' UEFI boot path work after flashing the JetPack 7 UEFI/QSPI firmware on Orin?
- Does Waveshare's IO-BASE hold 40 W thermally with the supplied cooler?
- How much does MAXN Super help nv1's memory-bound workload?
