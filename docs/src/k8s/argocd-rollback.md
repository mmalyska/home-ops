# Rolling back an ArgoCD application

Argo CD refuses a rollback while auto-sync is on
("Rollback cannot be performed against an application with automated sync enabled").
Our Applications are generated by ApplicationSets, and the ApplicationSet controller resets any hand edit
of an Application to the template, so turning auto-sync off in the UI is reverted within seconds.

## The escape hatch

An ApplicationSet can tell its controller to leave chosen fields alone with `ignoreApplicationDifferences`. We ignore only the auto-sync switch:

```yaml
spec:
  ignoreApplicationDifferences:
    - name: bookorbit # trial: one app; drop `name` to cover every app of the ApplicationSet
      jsonPointers:
        - /spec/syncPolicy/automated/enabled
```

Everything else, `prune` and `selfHeal` included, is still enforced from git.

Enabled for: `bookorbit` (`appset-default`), as a trial.

## Procedure

1. In the Argo CD UI, open the app and click **Disable Auto-Sync**. The UI keeps the `automated` block and writes `enabled: false`.
2. **History and rollback**: pick the last good revision and roll back.
3. Fix git: revert or fix the bad commit and merge it.
4. Click **Enable Auto-Sync**. The app syncs to the fixed git state.

Do not re-enable auto-sync before step 3: it syncs the bad revision again.

## Caveats

- After the app exists, `syncPolicy.enabled` in `app-config.yaml` is only the value at creation. Changing it in git does not reach the existing Application; toggle it in the UI as well.
- An app left with auto-sync off silently stops following git. Check `argocd_app_info{autosync_enabled="false"}` after a rollback.
- Argo CD issue [#22803](https://github.com/argoproj/argo-cd/issues/22803) reports apps going to `Unknown`
  with `ignoreApplicationDifferences` and `templatePatch` (multi-source apps, jq over a list).
  Our apps are single-source and use a plain JSON pointer; the bookorbit trial is there to confirm it.
- Upstream PR [#29926](https://github.com/argoproj/argo-cd/pull/29926) would allow rollback with auto-sync on. If it ships, prefer it and drop this rule.

## How it was verified

On Argo CD v3.6.1, on 2026-11-13, with a throwaway ApplicationSet carrying the rule:

- `enabled: false` set by hand survived forced ApplicationSet refreshes.
- `argocd_app_info` reported `autosync_enabled="false"` at the next scrape.
- A hand edit of `selfHeal` was reverted by the controller, so only the ignored field is left alone.
