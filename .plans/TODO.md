- [ ] **`task talos:wait_for_health` blocks on any lingering failed Job.** Found 2026-10-12, still present 2026-10-20. The first line of the gate (`.taskfiles/talos/Taskfile.yaml`, `wait_for_health`) is `kubectl wait --timeout=5m --for=condition=Complete jobs --all --all-namespaces`. A Job that failed (for example one transient `talos-backup` failure, BackoffLimitExceeded) never reaches `Complete`, so `kubectl wait` burns the whole 5 minute timeout on it, and `task talos:apply`, `talos:upgrade` and `talos:upgrade:all` (all use the gate) stop before touching the node. A CronJob keeps one failed Job (`failedJobsHistoryLimit`), so one failed run of any backup CronJob blocks the gate until the next run replaces it. tuppr's own gate is not affected (its Jobs check only looks at `status.active`). Fix, smallest first: wait only for Jobs that are still running (list Jobs with `status.active > 0` via `kubectl get jobs -A -o json | jq` and wait for those, so a failed Job is ignored and a running backup still holds the gate); keep the Ceph and CNPG waits. Same semantics as the tuppr check (`!has(status.active) || status.active == 0`). Consider printing failed Job names as a warning. Check `docs/src/` and `provision/talos/README.md` for text that says the gate waits for all Jobs.
